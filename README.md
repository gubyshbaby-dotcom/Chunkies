# Chunkies

Серверный мод для **NeoForge 1.21.1**, который ускоряет генерацию, загрузку и отправку чанков.
Ставится только на сервер: игрокам ничего устанавливать не нужно, ванильные клиенты подключаются как обычно
(в одиночной игре тоже работает — там сервер встроенный).

Мод не меняет сам мир: та же местность, те же структуры, тот же формат сохранений. Он меняет только то,
*как быстро* сервер проходит путь «чанк нужен игроку → чанк у игрока на экране».

## Что именно он делает

В ванильной 1.21.1 прогрузка чанков упирается не в железо, а в устройство самого конвейера. Ниже — узкие
места, найденные профилированием, и что с каждым сделано.

| Узкое место в ванили | Что делает Chunkies |
| --- | --- |
| Почти все шаги генерации (структуры, поверхность, пещеры, фичи) идут в **одном потоке** на измерение; по ядрам расходятся только шум и биомы. С модами на генерацию этот поток и есть главный тормоз. | Шаги генерации выполняются пулом рабочих потоков. Шаг блокирует все чанки, в которые может писать (свой, а для фич — ещё и соседние), так что два шага с пересекающимися областями никогда не идут одновременно. |
| Работа размазывается по всем чанкам в очереди, поэтому после телепорта в новую местность долго не появляется ничего. | Очередь упорядочена по графу зависимостей генерации: шаг тем срочнее, чем ближе к игроку чанк, который без него нельзя закончить. Сначала закрывается «конус» работ под ближайшим чанком. |
| Проверка «может ли тут начаться структура» (высота, биом) для сотен модовых структур идёт строго по одной. | Проверки идут параллельно; сама сборка структуры из кусков по-прежнему строго по одной (там у ванили и модов общее изменяемое состояние). |
| Одновременно «в работе» может быть только **4** чанка игрока, остальные ждут — сервер простаивает, пока задачи перекидываются между потоками. | Очередь расширена (по умолчанию 32 чанка на рабочий поток). Порядок «ближние первыми» сохраняется. |
| Чанк с диска целиком разбирается на главном потоке сервера. | Блоки и биомы секций декодируются в фоновых потоках, главный поток получает готовое. |
| **Каждый** загруженный чанк сразу помечается изменённым (побочный эффект загрузки света и структур) и при выгрузке заново сериализуется и пишется на диск — на главном потоке, даже если в нём ничего не трогали. | Загруженный чанк считается чистым, пока в нём действительно что-то не изменится. Чанки, обновлённые со старой версии игры, один раз пересохраняются как и раньше. |
| При загрузке чанка движок света шлёт ~50 уведомлений «свет изменился» на главный поток, хотя свет просто прочитан с диска; каждое помечает чанк и соседей изменёнными. | Уведомления без реального изменения значений света пропускаются. Настоящие изменения света обрабатываются как в ванили. |
| Поток освещения запускает обработку только когда главный поток свободен. | Поток освещения запускает её сам, как только получил задачи. |
| Готовые задачи чанков выдаются главному потоку **по одному чанку**: выдали, дождались ответа через пул потоков, выдали следующий. Чанк, которому осталось только «стать готовым», стоит в этой очереди ~130 мс при простаивающем главном потоке. | Главному потоку выдаётся пачка (до 32 чанков) за раз, в том же порядке приоритетов. |
| Игроку отправляется столько чанков за тик, сколько запросил его клиент (обычно немного) и не больше 64. | Запрошенная клиентом скорость умножается (по умолчанию ×2, не меньше 8 и не больше 128 чанков за тик). Подтверждения от клиента по-прежнему управляют потоком. |

Отдельно мод следит за тем, чтобы ускорение чанков не шло за счёт TPS: задачи чанков могут задержать
следующий тик не больше чем на 25 мс (в ванили — до 50 мс), а если главному потоку не хватает процессорного
ядра, число рабочих потоков генерации временно уменьшается.

## Замеры

Тестовый стенд: 4 ядра, NeoForge 21.1.265, один игрок, сервер и клиент-бот на одной машине. Каждая строка —
время от запроса до получения клиентом **всей** области видимости.

**Сборка из 37 модов на генерацию** (Terralith, Tectonic, Biomes O' Plenty, Oh The Biomes We've Gone,
Regions Unexplored, все YUNG's, When Dungeons Arise, Towns and Towers и др.), дальность 10 (453 чанка):

| Сценарий | Без мода | С Chunkies |
| --- | --- | --- |
| Телепорт в **новую** местность — появился первый чанк | 4.3–9.4 с | 2.6–5.7 с |
| Телепорт в **новую** местность — прогружена вся область | 62–78 с | 39–51 с |
| Телепорт в уже сгенерированную область (чтение с диска) | 1.6–2.7 с | 1.0–1.8 с |
| Вход на только что запущенный сервер | 4.3–5.3 с | 3.5–3.8 с |

**Чистый NeoForge без модов на генерацию:**

| Сценарий | Без мода | С Chunkies |
| --- | --- | --- |
| Телепорт в **новую** местность — появился первый чанк (дальность 12) | 1.6–2.7 с | 1.1–1.3 с |
| Телепорт в **новую** местность — прогружена вся область (дальность 12, 609 чанков) | 28–38 с | 21–26 с |
| Телепорт в уже сгенерированную область (дальность 12) | 1.8–2.1 с | 1.4–1.6 с |
| Клиент, запрашивающий мало чанков за тик (5), дальность 16, 1021 чанк с диска | 10.3–11.3 с | 5.2–6.4 с |

Диапазоны — разброс между прогонами (на общем тестовом железе он около ±10%). TPS сервера во всех прогонах
оставался около 20.

Важно понимать, откуда берётся выигрыш:

* **Генерация новых чанков** ограничена процессором. Мод не делает саму генерацию дешевле — он раздаёт её по
  ядрам. На 4 ядрах это ×1.3–1.6; чем больше ядер у сервера, тем больше прирост (на стенде больше 4 ядер
  не было, так что это ожидание, а не замер). «Мгновенной» генерация
  новой местности не станет ни с каким модом: если нужна именно мгновенная прогрузка — мир нужно
  сгенерировать заранее (например, модом Chunky), а Chunkies ускорит и саму предгенерацию.
* **Загрузка уже существующих чанков** в ванили ограничена не железом, а очередями и лишней работой главного
  потока — здесь выигрыш почти не зависит от числа ядер. Помимо скорости, главный поток просто делает меньше
  работы: за двухминутный тест пропускается около миллиона пустых уведомлений о свете, а чанки, мимо которых
  игрок только прошёл, больше не пересохраняются.

## Установка

1. Скачайте или соберите `chunkies-neoforge-1.21.1-<версия>.jar`.
2. Положите его в папку `mods` сервера. На клиенты ставить не нужно.
3. Запустите сервер. Настройки появятся в `config/chunkies.toml`.

Команда `/chunkies` (для операторов) показывает состояние: сколько рабочих потоков активно, сколько шагов
генерации в очереди, сколько работы снято с главного потока.

## Настройки (`config/chunkies.toml`)

Все функции включены по умолчанию и отключаются по отдельности.

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `tickets.playerTicketConcurrency` | `0` (авто) | Сколько чанков игроков одновременно в работе. Авто = 32 на рабочий поток, минимум 64. В ванили 4. Нужен перезапуск. |
| `worldgen.parallel` | `true` | Параллельная генерация. Выключите в первую очередь, если какой-то мод на генерацию ведёт себя странно. |
| `worldgen.parallelStructureStarts` | `true` | Параллельные проверки мест для структур. Выключите, если проблемы именно со структурами. |
| `worldgen.threads` | `0` (авто) | Число рабочих потоков генерации. Авто = ядра − 1. Нужен перезапуск. |
| `worldgen.yieldToServerThread` | `true` | Если тик не укладывается во время из-за нехватки процессора главному потоку — временно использовать меньше рабочих потоков (но не меньше половины). |
| `loading.offThreadParsing` | `true` | Декодирование секций чанка вне главного потока. |
| `loading.eagerLightScheduling` | `true` | Поток освещения не ждёт главный поток. |
| `loading.skipRedundantSaves` | `true` | Не пересохранять чанки, которые только загрузили и не меняли. |
| `pipeline.dispatchBatch` | `32` | Сколько чанков за раз выдаётся главному потоку. 1 = как в ванили. |
| `pipeline.lateTickAllowanceMs` | `25` | На сколько миллисекунд задачи чанков могут задержать следующий тик. Меньше — ровнее TPS, больше — быстрее чанки, когда узкое место в главном потоке. В ванили 50. |
| `sending.enabled` | `true` | Ускоренная отправка чанков игрокам. |
| `sending.rateMultiplier` | `2.0` | Множитель к скорости, запрошенной клиентом. Больше — быстрее заполняется обзор, но слабым клиентам тяжелее в момент прогрузки. |
| `sending.minChunksPerTick` | `8.0` | Нижняя граница отправки за тик. |
| `sending.maxChunksPerTick` | `128.0` | Верхняя граница отправки за тик (в ванили 64). |

## Совместимость и ограничения

* Проверено на сервере с 37 модами на генерацию мира: генерация, загрузка, перезапуск, сохранность
  изменений — без ошибок.
* Параллельная генерация — самая «чувствительная» часть. Мод на генерацию, который хранит рабочее состояние в
  статических полях и рассчитывает на единственный поток генерации, теоретически может с ней конфликтовать.
  Сборка структур из кусков и спавн мобов при генерации специально оставлены последовательными, а всё
  остальное отключается одной строкой в конфиге.
* Не ставьте вместе с другими модами, которые переписывают ту же часть игры (порты C2ME и подобные).
* Освещение по-прежнему считается одним потоком на измерение: на серверах с большим числом ядер следующим
  ограничителем генерации станет оно.
* Сохранение изменённых чанков осталось на главном потоке, как в ванили.
